# Process log: VirtualTourism, The Night Walk Chapter (from prompt to deployment)

Use `#process-log` to give Kiro the history, decisions and pitfalls. Also the basis for the Kiroween "How Kiro was used" write-up.

## 1. Specs first (2026-11-23)
`appgenprompt.md` was split into eight specs (core, auth, db, admin, blender, content, ui, user), each with requirements, design and tasks. Steering files were added: always-on project context, a Blender workflow that loads when `.glb/.gltf/.blend` files are touched, and a manual web-research prompt.

## 2. Research and reference material
- Agent research (web search and fetch) gathered facts, licensed photos (Wikimedia Commons CC BY / CC BY-SA), OSM coastline and roads, a 90 m elevation grid (Open-Meteo), and a museum visitor map supplied by the user.
- The visitor map is rotated about 180 degrees (image-up = south). Found by comparing the OSM coastline (east of the museum pin) with the map's sea (image-left). All 37 numbered map points were transcribed to `reference/sitemap/site_layout.json` with real-world metres.
- User-supplied vlogs were used only as visual reference (frames, OCR for signs). Transcripts were low quality and were not used as sources. They are git-ignored, as are the museum map and blog photos.
- Evidence and confidence per hotspot live in `reference/photos/<slug>/INFO.md`, `reference/NOTES.md`, `reference/sitemap/MAP_NOTES.md`.

## 3. Tooling via MCP
- Blender MCP (`mcp-for-blender`) controlled a live Blender 5.3: build, inspect with rendered views, save, export.
- OpenStreetMap MCP needs `uvx --with "mcp<2" osm-mcp-server` (mcp 2.x breaks it). Only reverse geocoding worked; nearby-places returned HTTP 406. Geometry came from the Overpass API directly.
- Poly Haven assets (CC0) were fetched with `blender/scripts/fetch_polyhaven.py`.

## 4. 3D model pipeline (`blender/scripts/`)
`build_muzium.py` (terrain from DEM and OSM coast, 37 map structures, facilities, paths, road, hotspot and loc empties, spawn) then `place_props.py` (Poly Haven props decimated to a few hundred to a few thousand triangles, low-poly trees, scatter) then `export_muzium.py` then `optimize_glb.sh` (dedup, instance, weld, simplify, resize 1024, WebP, Draco). Result: 10.8 MB GLB, 57 `loc_*` markers, 10 hotspots, 5 walkable meshes.
Lessons: Poly Haven models are scan quality (trees 1-2 million triangles), so use them only for small props and build trees procedurally. `gltf-transform optimize/flatten/join` prune empty nodes and delete all markers. A comment swallowing a `;`-chained line removed the spawn link once.

## 5. App build
Flask app, models, OAuth (Google, Microsoft, GitHub, plus demo login and a judge admin key), admin panel with CSRF and safe uploads, seed with 10 hotspots, generated narration (Kokoro-82M offline, British female `bf_emma`, chosen by the user after comparing macOS `say`, Piper and Kokoro samples; `content/make_narration.py` regenerates it), web-sized licensed images, vendored Three.js with Draco, compiled Tailwind. Viewer: night atmosphere with lantern, fireflies and fog; walking, touch joystick, teleport, collisions; hotspots with panel, facts, audio; places drawer; WebXR plus Cardboard split-screen with gyroscope and gaze selection.

## 6. Verification done
- Route, login, admin, CSRF, upload and cascade-delete checks with the Flask test client.
- Headless Edge (SwiftShader): no console errors; viewer loads in about 8 s on a software renderer; 64 draw calls; walking, hotspot panel, touch joystick, Cardboard split-screen rendered.
- Bugs found by running it: help dialog unreachable on a landscape phone (fixed); `.hud-btn` CSS overrode `hidden` (fixed); gunicorn could not import `app:app` (added `wsgi.py`); two workers could race the first seed (added `--preload`).
- Repo hygiene: 149 files, about 17 MB, `.kiro` tracked, no secrets, no unlicensed media.

## 7. Hooks
`rebuild-tailwind-on-save` (PostFileSave on templates, `src.css`, viewer scripts) and `glb-size-budget` (PostFileSave on `app/static/models/*.glb`, warns above 40 MB since the realism pass).

## 8. Hackathon decisions
Category: Costume Contest (immersive, spooky UI; "Ghost Hill after dark"). Skeleton Crew was possible but needed a second destination. Rules summary (AWS blog, Oct 31): public GitHub repo with OSI licence and `/.kiro` untouched by `.gitignore`; live app URL; demo video under 3 minutes on YouTube; Kiro-usage write-up; judged on impact, Kiro implementation, design, innovation, presentation (20% each).

## 10. Guided tour (2026-11-25)
Request: two exploration types, the current self-controlled one and a guided one (no control, but look around in a headset). Built as: routes computed in Blender (A* on the real model, mirroring the viewer's movement rules), `GuidedTour.js` state machine, a start-screen mode picker, a HUD toggle and tour controls. Comfort choice: fades between stops in VR instead of continuous walking. Lessons: (1) the grid was too coarse for the 1.2 m wide stairs, so those are routed by hand; (2) a rail blocked the stairs, found because the route planner reported the tower unreachable, so the 3D model was fixed; (3) the goal test needs a height check or the hill above a tunnel counts as arrival; (4) audio autoplay needs a click, so the picker is always shown for the guided tour; (5) leaving the tour left a stale target height in the movement system, caught by walking after the tour in the browser test. Tests ran the whole tour at 10x speed in headless Edge and checked every stop, UI state, phone landscape and Cardboard.

## Realism pass and nature ambience (2026-11-25)
- Realism: ambientCG CC0 PBR materials, Poly Haven CC0 HDRIs (`qwantani_night_puresky` night, `fish_hoek_beach` day, 1K), windows/plinths/gate/lamp posts, procedural gun barrels, vertex-colour weathering. GLB 13.2 MB (budget 15 MB). Sketchfab, Quixel, CGTrader and Scan The World were rejected (licence or login).
- Nature ambience: `app/static/js/Ambience.js` plays three Web Audio loops (crickets, waves, wind) from `app/static/audio/ambient/`. The loops are synthesised by `content/make_ambience.sh` with ffmpeg, so there is nothing to credit. Starts on the first user gesture; HUD "Sound" button toggles and remembers the choice (localStorage `vt_ambience_muted`); ducks to 45% under narration; waves swell toward the east shore (spawn.x + 260 m); crickets drop by day.
- Entrance bug (user: "after the gate i cannot enter the building"): the new gate's own terrain pad overrode the ticket building's pad and raised the ground 1.8 m at its east door. Fix: the gate stands on the existing ground. Lesson: `site()` pads applied later win, so do not reserve pads next to buildings.
- Realism pass 2 (user chose "better buildings" and "higher size budget"): budget 15 MB to 40 MB; ambientCG 2K; real roofs, glazed windows, gutters, downpipes, pilasters, open doors, Poly Haven wall lamps over each door, ticket canopy; Poly Haven trees thinned by `thin_tree.py`. GLB 37 MB. No CC0 realistic WW2 building kit exists without login, so buildings stay scripted.
- Trees, option "denser plus hero trees": 38 background trees at 20% leaves, 6 hero trees at 50% leaves with a fuller trunk near the entrance and main stops. Found and fixed a frame-rate bug: glass with `transmission` makes three.js render the scene twice per frame; ModelLoader now disables it (2.07M to 1.03M triangles per frame). GLB 37.6 MB.
- Ambience, user feedback "crickets don't sing non-stop; by day birds, not crickets": two cricket layers (left and right) that each sing 4-18 s and pause 1.5-9 s at random; crickets silent by day; random bird calls (4 synthesised phrases, random pan, level and pitch) by day; gecko (cicak) every 14-40 s and owl every 35-90 s at night. All sounds still synthesised by `content/make_ambience.sh` (ffmpeg); the wind loop was nearly silent before and is now audible.
- Floating trees (user report): the scanned trees lean, so the bounding-box centre was not above the trunk, and on slopes the ground under the trunk was lower than at the centre. Fix in `place_props.py`: tree origin at the trunk base (`base_r` = trunk footprint radius); `settle_z()` puts every scattered tree, shrub, rock and stump at the lowest ground point under its footprint, sunk a further 10% of the radius. Blender check prints the worst gap (0.0 m); browser check: all 44 trees 0.2 m or more into the ground.
- More trees (user: "need more trees"): two new cheaper tiers in `place_props.py`. Far trees (85, `T_FAR1/2`, 8-9% leaves, 2.5k trunk) at least 11 m from paths; distant trees (130, `T_DIST`, 4% leaves, about 3.5k triangles) at least 32 m from paths and buildings so they never block a view up close. Trunks at least 6 m apart. Total 253 trees (38 background, 6 hero, 85 far, 130 distant); scene 2.13M triangles in 402 instances. GLB 37.8 MB (budget 40 MB).
- Frame-rate work for the extra trees: three.js culls an `InstancedMesh` as one object, so one tree type spread over the whole site was always drawn. `ModelLoader.chunkInstances(root, 70)` splits instanced meshes into 70 m grid chunks so frustum culling works; `viewer.js` hides chunks beyond the fog every 0.3 s (170 m at night, 520 m by day). Drawn triangles per view: about 570k at night (was 0.86-1.13M before fog hiding).
- Day sky: `fish_hoek_beach` showed beach huts and a person on the horizon, so day is now Poly Haven `kloofendal_48d_partly_cloudy_puresky` (CC0, 1K). Day light toned down (environment 0.55, hemisphere 0.45, sun 1.9, exposure 0.9, fog `0xa9c4d8` 0.0035) because the scene looked washed out.
- Checks after the change: headless Edge, no console errors; every tree at least 0.17 m into the ground, none above it; walk through the ticket building passes; guided tour routes rebuilt (599 m, all 10 stops reachable). Not yet measured on a real phone: more trees cost GPU time, so if the phone stutters, reduce `T_DIST`/`T_FAR` counts first.
- Layout match (user: "make it match at least on the positioning of buildings and tree first", with `site-model.jpg` and a reeaki.com map photo as references): plotted the model plan over Esri satellite tiles and OSM (peak, footway). The fort core was rotated 55° counter-clockwise (`LAYOUT_ROT`), while features tied to the road and coast stayed fixed. The car park moved to the gravel area north of the ticket building, and the core forest was densified (303 trees) with clearings for the ridge track and car park. Fallout fixed along the way: the rotated memorial landed inside tunnel 29 (moved to 30,-76); the hillside cut through tunnel 29 (terrain now carved under tunnels); the escape-route hotspot was unreachable (moved to the crawl mouth); the tunnel mound's end face hid every portal (new `G.mound()` with an opening); the lookout fact said "a few hundred metres" to the coast (now about 150 m). GLB 38.2 MB, 2.47M triangles; tour 540 m, all stops reachable; float, door, chunk and tour browser checks pass. Lessons: (1) rotating a layout moves things into each other, so re-run the route planner, which finds blocked hotspots; (2) look at every tunnel portal from outside after a terrain change; (3) satellite and reeaki images stay private in `reference/inbox/` (Esri licence, third-party photo).
- Phone-friendly assets (user: "in polyhaven try to source image to make it suitable for mobile phone, 1K textures, 2K textures, low polygon count"). Trees were 93% of the 2.47M triangles, so the polygon work went into trees. All building and ground materials now come from Poly Haven (CC0), downloaded at 1k and 2k and picked against the old ambientCG ones on contact sheets. `export_mobile.py` writes a second, phone model with the 1k files and one-tier-cheaper trees (14.7 MB, about 0.9M triangles). The desktop model keeps 2k (34.9 MB). The viewer chooses by device, with a `?quality=` override. Phone emulation draws about half the desktop triangles (251k–476k per view), and the float, door, chunk and tour checks pass. Lessons: (1) Poly Haven names colour maps `_diffuse_`, not `_diff_`; the old matcher would have found no colour map, so check the downloaded file names before wiring a new source; (2) the Blender MCP session can restart with an empty scene, so check the scene before running a single later step; (3) with `?quality=full` the phone emulation could not finish loading the full model within 3 minutes, which supports serving phones the light model.
- Building detail (user: "search from the web more info on the buildings… the dimension if possible, the interior, try to copy as close as possible"). Web research found no published dimensions or plans. The UiTM paper covers dark tourism, Wikipedia could not be fetched, travelmalaysia and travelfish block scripted downloads, and Commons holds only our 22 photos. Dimensions were therefore taken from the photos and from the standard 1930s 6-inch BL coast battery pattern (Pasir Laba and Heugh batteries, Singapore). New builders: `gun_bay()` (points 25 and 36), `lockup()` (points 19 and 20), `exhibits()` (barracks and exhibition rooms), plus the memorial fence, whitewashed tunnels with lamps and the covered walkway. Day screenshots from 8 cameras (`/tmp/pw/view2.mjs`) found two faults. The hillside rose through the inner end of tunnel 29 because the 6 m terrain grid is coarser than the carve band, so the terrain is now refined to 1.5 m around tunnels. The lock-up doors opened outward against the brick walls; they now open inward, with the brick walls set back as in `cell-door-1.jpg`. Desktop 35.0 MB, phone 14.7 MB; all browser checks pass. Lessons: (1) a vertex-based terrain carve must be finer than the feature it carves, so check with a ray along the floor; (2) compare new builders against the matching reference photo before signing off.
- Strict sitemap layout (user: "strictly follow guideline based on the sitemap from https://i0.wp.com/reeaki.com/…photo_2021-03-24_12-51-55.jpg"):
  - The image is the reeaki "Fort Relics" map photo (same file as `reference/inbox/reeaki_map.jpg`).
  - New `blender/scripts/extract_reeaki.py` turns it into `reference/sitemap/reeaki_layout.json`: the 37 markers read by eye on zoomed grid crops, building angles, facilities and coast dots, a height field from the drawn hill, bay and sand bar, path skeletons, hand-traced roads and 83 tree groups.
  - Removed: the 55° `LAYOUT_ROT`, the fixed points, the satellite car park and clearings, and the DEM terrain.
  - Desktop 34.9 MB, phone 14.7 MB. All 10 stops reachable, all browser checks pass, hotspots re-synced.
  - Lessons:
    1. Automatic marker detection failed on the small, compressed photo (red-ring and white-disc tests matched icons and labels). Reading the markers by eye on 3× crops with a 20 px grid was faster and more reliable.
    2. Subtracting the ticket height after the coast blend pushed the beach under the water. Normalise heights before applying sea level.
    3. Gaussian smoothing sinks narrow land such as the sand bar. Clamp land cells above the water after smoothing, then drop leftover specks.
    4. A tunnel aimed straight uphill can run under the next building in a dense layout. Check the far end against the other points.
    5. White roofs on the map look like paths to a skeleton. Cut paths with the building footprints.
- More Poly Haven models for phones (user: "use as much models source from polyhaven which suitable for mobile phone 1K or 2K textures or with log polygon count"). I searched the Poly Haven API for low-poly models that fit the site and reviewed the thumbnails. 34 more CC0 models are now in use: room furniture and clutter in 7 buildings, outdoor items, tropical understory, rocks, fallen wood and coastal rock faces. Small-prop textures are capped at 512 px in `optimize_glb.sh`. Desktop 34.8 MB, phone 14.6 MB, all checks pass. Lessons: (1) plant scans are life-size, and some are only centimetres tall; (2) Poly Haven files often hold several variants, so split them per variant; (3) the cost of extra assets is texture size, so cap small-prop textures.
- Opening flight (user: "when start the game it camera from top and slowly go to entrance"): new `IntroFlight.js`, 11 s from 175 m above the fort down through the entrance gate to the spawn point, with a title card and a Skip button, then the mode picker. It is skipped for `?intro=0`, reduced motion and automated browsers. Lessons: (1) headless swiftshader renders the top view at about 1 frame every 3 s, so check camera moves with frozen frames (`/tmp/pw/intro_frames.mjs`) instead of real time; (2) time cinematic moves by the wall clock, not by the clamped frame delta; (3) the intro exposed that `placeAt()` started the visitor 2 m in the air (ray reach too short), now fixed.
- User models (user: "replace the 2 pillbox in our map with this one, also substitute the entrance with the in blender folder at desktop/blender"; then "use penang_war_museum_entrance1"). New `user_models.py` bakes the user's .blend files into the scene: type-1 pill boxes on the hill (1, 2, 27, 37), sunken type-2 pill boxes on the coast with the terrain carved, and the entrance in place of the scripted gate (spawn moved outside it). Desktop 37.8 MB, phone 15.3 MB, all checks pass. Lessons: (1) the Blender MCP shares the user's Blender session; the user opened and edited their own files during the task, so check `bpy.data.filepath` and `is_dirty` before running anything that clears the scene, and stop when the user is working; (2) appending objects drops their collections, so append the collections too when roles depend on them; (3) the view script's ground ray only reached 40 m below 30 m, so shots at the shore floated; pass a longer reach.
